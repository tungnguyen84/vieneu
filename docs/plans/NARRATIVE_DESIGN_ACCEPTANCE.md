# P6 — Generator and grounded review acceptance

Date: 04–05 October 2026. Baseline: `48542c755d30e6f1c0ef70f71ee3099fca963c68`.

This change modifies generation, planning and review code. No submitted script, source snapshot, approved Story Bible or acceptance script was edited by hand. Generated prose changes only through the Studio production UI and the configured OpenAI-compatible provider. Audio Formula V1, Flow and assembler implementation are unchanged.

## Root causes and changes

1. Equal word budgets per provider call assigned too many words to the last reflection/signoff group. An ending could meet length requirements by retelling the whole journey. Scene roles now allocate the budget to dramatic work, cap reflection/signoff at 8%, and keep the actual payoff funded. Closing is a separate call.
2. Every long-form call received the complete outline and instructions to perform the whole ending. Adjacent calls repeated repairing and handing over the same object. Each call now gets active scene actions, fixed canon, the preceding prose and explicit next-scene boundaries. Scene IDs must be ordered, complete and confined to the assigned group. Content review remains necessary: a scene label alone is not proof.
3. Planner and writer could treat a changed feeling or a plan to pay as completion. Scenes record actual before/after states and a listener question. Ending review requires verbatim Bible actions and cited completed actions with the correct person, object, occurrence and resources. A payment-specific guard rejects earmarking money or a previous payment as the promised new payment. Factual unknowns/plans stay unknown/planned.
4. A reviewer could flag one allowed reflection as a critical long ending, or flag repeated events without quoting both occurrences. Repetition now requires original/later quotations. Long-episode closing checks cite the last new event and calculate the trailing word fraction from prose, regardless of delivery labels; a genuinely excessive tail targets the whole tail for revision.
5. Invalid review output could stop repair even when a separate objective finding was grounded. Bounded repair can use validated findings; an incomplete review still cannot approve anything. Invalid report quotations, paraphrased required actions and missing fields receive actual text and actionable schema feedback, with one report retry. Native and source review versions invalidate obsolete results.
6. Source review confused a general writing brief with an already narrated distinctive plot. It now distinguishes generic themes/brief requirements from copied specific scenes/dialogue, while keeping paired source/work evidence and two independent passes. Old source policy results cannot authorize current work.
7. A source answer may be in the next sentence of the same paragraph. Grounding now accepts distinct, non-overlapping quotations in forward order; reusing the discovery sentence or reversing them remains invalid.
8. A signoff has no obligation to change the already completed story state. Closing scenes may preserve that state; body scenes still require progression. Rejected outlines log and return concrete design/missing-payoff feedback for their one bounded retry.
9. Story re-audit during script generation was transient: rejection stopped the writer but left an old PASS on disk. Source Story reports are now saved at both existing locations under the project lock after a snapshot check. A failed audit reopens Story review and invalidates downstream approval without rewriting the approved canon. The failure includes the actual QC reason. A passing audit can be reused by subsequent requests instead of repeating unchanged work with an obsolete policy.
10. Free-form `required_action` copying proved unreliable even with report-retry feedback. Ending actions now have IDs bound by the backend to literal Bible clauses. Every bound action must be covered; missing IDs or invalid evidence still block. Existing literal reports remain accepted only when they cover the full current catalog.
11. A grounded closing verdict saying FAIL does not establish a breach of the numerical 10% rule. The backend measures the cited tail; over-limit tails remain critical even if the judge says PASS. Under-limit stylistic objections remain visible editorial warnings. This does not relax fact, payoff, source, lineage or approval gates.
12. Repairing each closing paragraph separately preserved too many closing paragraphs. A grounded over-limit suffix can now be rewritten by the real provider into one bounded reflection, preserving body/payoff and the final signoff. The entire candidate receives fresh QC; invalid compression preserves the draft.
13. After a correct closing compression, a global duration deficit was anchored to the opening segment. Ordinary targeted repair padded the hook. When duration is the only grounded defect, repair now redistributes the checked scene plan once; it cannot repeat this operation indefinitely. New repair requests also receive a current generation timestamp.
14. The initial writer JSON schema omitted `scene_no`, although later scope validation required it. The schema now includes the field, exact numeric strings are canonicalized, and retry feedback identifies incorrect/missing IDs. Missing, boolean, future or out-of-order IDs still fail.
15. A 10-minute whole-episode call repeatedly underfilled its word budget; a 25-minute closing call received incompatible global paragraph-count/65-word constraints. Checked source scripts over 1,000 words now use scoped batches. Closing gets exactly one item per closing scene, a local word budget and an explicit exception to the body paragraph-size instruction. A sole REFLECTION may contain its short final signoff. No prose is mechanically appended.
16. Narrowing the long-call Bible context discarded the concrete task because `concrete_instance` is nested in `narrative_skeleton`, not at the root. Scoped canon now preserves concrete_task/task_design/concrete_instance but excludes future key_scenes. Scene count guidance follows the actual duration, and prompts explicitly preserve physical handovers across calls.
17. A source reviewer returned empty source evidence even for a valid absence-of-copied-dialogue check. Every mode check still needs a real source context quote; rejection feedback now supplies actual unit IDs and valid quote examples. Absence must be explained in the reason, not established by an invented source quotation.
18. Segment repair prohibited adding a signoff even when MISSING_FINAL_SIGNOFF was the defect. It could also remove a valid final signoff while shortening a closing. The instruction now permits/preserves the signoff only at the final ID, and the application guard rejects final rewrites that drop a required real signoff. Mid-script signoffs remain rejected.
19. A real five-minute trial returned scene roles in `delivery_profile` despite one retry. Only known equivalent roles now map to voice profiles (PAYOFF/DECISION/etc → NORMAL, REFLECTION → COMMENT, SIGNOFF → ENDING). No text changes; spoken signoff and grounded content gates remain independent. Arbitrary unknown values remain invalid and rejection feedback includes the actual value, not just its index.
20. A sole closing scene received only 25 words to reflect and sign off. Closing now reserves up to 60 words within the unchanged 8% allocation cap, subtracting them from the body. A closing allowance is a ceiling, not a minimum quota to pad; the whole-episode duration check remains mandatory.
21. A long trial failed because a 52-word signoff exceeded its weighted 35-word share even though the combined close could fit. Reflection and signoff now share the same total ceiling. Adjacent JSON items from the same closing scene may be coalesced only if their combined prose already fits that ceiling and no earlier item contains a goodbye. All words are retained; overlong/duplicate goodbyes still fail and full content QC still runs. No template ending is inserted.
22. Reading the v12 long script revealed event prerequisites and a switch into design-report voice that two general review passes missed. Source pass two now has a distinct continuity task, reduced canon context, the selected POV and the full numbered prose. It checks chronology, locations and prerequisite actions before returning the same evidence/payoff/pacing contract. Cross-scene source continuity findings require two real quotations. The policy version invalidates prior approval gates; tests prove invalid quotations cannot authorize approval.
23. A later real review returned PASS for unchanged long prose after an earlier grounded chronology failure. Re-audit and revision now retain validated objective findings when the script/story hashes and the quoted scene plus nearby context remain unchanged. Changing an unrelated goodbye cannot clear the defect; changed anchors/context or changed canon require fresh review. Invalid quotations and editorial preferences are not retained. This conservative guard can require an actual contextual correction rather than repeated random rechecks.
24. An objective finding in pass one previously skipped the independent continuity pass, leaving repair with incomplete information. Grounded source reviews now run both passes even when pass one finds a defect, deduplicating matching findings. Incomplete reports still cannot approve. This introduced `semantic-v30-independent-continuity-and-retained-findings`; the final policy also includes the decision-ownership check described below.
25. A fresh long Story request failed at the clue schema. The exact lower-case alias of `what_it_does_NOT_prove` is now canonicalized without changing evidence; conflicting aliases still fail. A resolved detail may have an empty `next_question`; clue/proof/evidence-limit text remains mandatory. Retry feedback names the actual item/index/missing fields instead of repeating an opaque schema error. The subsequent production Story request succeeded; that does not prove which field was wrong in the earlier unsaved response.
26. A short ending required both parent and child to share, but the issue quoted the meal paragraph while the child's conversation was in the next paragraph. Targeted repair could only rewrite the anchor, leaving the incomplete continuation intact. A validated source PAYOFF_NOT_COMPLETED now permits repair of the next non-signoff paragraph too, preserving completed actions and preventing duplicate resolution. The source repair version is `source-adaptation-v1-writer-v13-payoff-continuation-repair`; every candidate still gets full QC.

27. A writer could label its final paragraph ENDING without an actual spoken goodbye. The writer now checks final prose for a real signoff during the bounded schema retry. It does not append a programme template. Tests reject label-only endings and accept an actual provider-written signoff.
28. Fresh EP2030 falsely failed its locked `adaptation_mode` fact because QC required `FICTION_FROM_THEME` in the narration. The field is now checked against both Story and Script source metadata, not spoken text. Missing/wrong mode remains a conflict, including when the enum is merely inserted into the prose. The current source gate is `script-qc-v5.9-source-metadata-facts`.
29. Reading EP2030 found unclear ownership of its first order quantity, and repeated cooperation agreements. Shared source prompts now distinguish confirmed customer orders from producer-controlled consignment/trial quantities, offers from acceptance, and compensation promises from completed payment. Story review and the independent Script pass must compare the decision with the attributed consequence, and recurring agreements with their changed conditions. Factual unknowns and own-script locks are preserved. Final policies: `source-adaptation-v1-story-v2-causal-decisions`, `source-adaptation-v1-writer-v14-causal-decisions`, `semantic-v31-causal-decision-ownership`. Prompt improvements do not themselves prove a draft correct.
30. Source Auto-Repair checked Script but could reuse an obsolete Story audit while trying to fix prose constrained by an internally inconsistent canon. It now audits the current Story first using the same provider, persists the report to both Story locations under the existing lock/snapshot checks, and stops before any prose repair if the Story fails or review is unavailable. The UI returns to a Story needing review and stales the downstream Script; no hidden rewrite of canon is allowed. Regression tests cover both FAIL and ERROR and prove narration/request IDs remain unchanged.

31. A real Story reviewer quoted a literal `key_scenes` decision but labelled it with the sibling `task_design` alias. Known skeleton aliases now resolve a misplaced quotation only when it occurs in exactly one real skeleton leaf. The original field is retained in `reported_field`; quote/verdict/canon are unchanged. Ambiguous matches, paraphrases and invented aliases remain errors. This is metadata normalization, not acceptance of fabricated evidence.
32. EP2028 had current PASS and a quantified 106/1,594-word closing advisory, but the approval gate classified the advisory's rule name as critical anyway. The gate now preserves the specific `REDUNDANT_CLOSING` advisory only when it is explicitly WARNING and `blocking=false`. The same code in `issues`, critical/explicitly blocking advisories, and other objective findings still block. Old reports, mismatched lineage and absent Script approval cannot be overridden by a warning. Five gate cases plus stale-review/approval negative controls cover this regression.

## Limits of acceptance

QC PASS means the configured objective gates have current evidence; it is not a guarantee of compelling writing, audience retention, views or readiness to publish every draft. Whole-script reading is required to assess pacing and dramatic specificity. The content-based quantitative pacing proof currently applies to scripts with at least 20 segments; shorter scripts retain grounded payoff/source checks and manual pacing assessment.

No TTS, background music mixing, final render or YouTube publication is part of this P6 live acceptance. Those stages are not certified by script QC. Test failures inherited from the baseline are reported separately rather than hidden.

2. Reload the browser and confirm the same request ID/content hash and current QC report. The committed evidence JSON records both reads.
3. For another sample, create a new episode, set its duration, paste an authored reference and choose FICTION_FROM_THEME. Confirm source, select one direction, generate/review/approve Story, then generate Script. A failed job must show its actual error and preserve the previous draft, not silently approve it.
4. Approve only after reading. NEEDS_REVIEW before approval is intentional; Audio remains blocked even when current QC passes. Never use a hand-edited runtime JSON as generator acceptance.
